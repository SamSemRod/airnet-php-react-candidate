# Использование ИИ

## Инструменты и делегированные задачи

Если ИИ не использовался, укажите это.

Использовал Claude Code (агент в терминале с доступом к файлам проекта,
Docker и git). Ему я поручал:

- разобрать задание и код, составить план работ, запустить проект;
- написать автотесты Playwright (API и UI) до исправлений и прогнать их на
  исходном коде;
- внести исправления в бэкенд и фронтенд отдельными коммитами;
- подготовить черновик SOLUTION.md по фактическим результатам.

Сам я воспроизводил проблемы руками, выбирал инструмент тестов и порядок
работы, проверял diff, прогонял тесты и смотрел UI в браузере.

## Один существенный пример

Задача, контекст и ограничения, которые вы дали модели:

Контекст — распакованный проект и файл задания (`Задача.docx`, README.md,
docs/api.md). Ограничения взяты из задания: PHP 7.4 без фреймворков,
`pg_query_params`, React 18, задержки API не убирать, авторизацию, CSRF и
окружение не переписывать, diff должен быть небольшим. Работа шла в два
запроса: сначала план, потом реализация по нему.

Существенный запрос либо его точное смысловое содержание:

Первый запрос:

> Прочитай `Задача.docx` и файлы проекта. Запусти демо по инструкции; если
> возникнут сложности, задай уточняющие вопросы. Составь план решения в
> отдельном .md-документе и положи его вне папки проекта: какие шаги нужны,
> чтобы выполнить всё из задания, и что сделать перед началом работы.


Второй запрос — после того как я прочитал и поправил план и сам воспроизвёл
ошибки:

> Начинаем решать по плану. Я его немного поменял, обрати на это внимание.
> Репозиторий и начальный коммит я уже сделал.
> Проверь, уместен ли по заданию Vitest: мне кажется логичнее использовать
> Playwright. По мере появления ответов заполняй SOLUTION.md, но оставляй
> вопросы шаблона, чтобы я мог сверить ответы с вопросами.

Предложение модели и соответствующее изменение в коде:

По плану модель сначала нашла причины по коду и подтвердила их запросами к
запущенному API: 500 на заявке 103, 200 на изменение от роли «Просмотр»,
200 на изменение архивной 104, лишняя запись истории при повторе источника,
400 вместо 404 при неверном порядке проверок. Гонку в UI нашла по коду:
у эффекта загрузки нет отмены.

Во втором запросе:

1. Подтвердила выбор Playwright: в задании инструмент не указан, а в
   `.gitignore` проекта уже есть `test-results/` — папка вывода Playwright.
   Написала 36 тестов в `e2e/` и прогнала их на исходном коде: 12 упали.
   Закоммитила тесты отдельно (`4e4a902`).
2. Бэкенд (`96ead9c`): проверка `FUNC_TICKETS_SOURCE_EDIT` первой строкой
   маршрута; `changeSource()` в транзакции с `SELECT … FOR UPDATE`; порядок
   проверок «заявка, архив, источник» через исключение `ApiError` с откатом
   транзакции; `LEFT JOIN` в `find()`. По ходу нашла ещё одну проблему: `id`
   больше 2147483647 давал 500. Добавила на неё тесты.
3. Фронтенд (`bb3a42a`): флаг `active` в эффекте загрузки и сравнение id
   сохраняемой заявки с выбранной через `useRef` в `save()`.

## Проверка результата

Что проверили самостоятельно и каким способом?

- До исправлений руками воспроизвёл все три проблемы: в браузере (101, потом
  сразу 102; карточка 103) и через curl (`POST` от роли «Просмотр»).
- Сверил, что тесты на коммите только с тестами падают именно на нужных
  проверках. Например, UI-гонка падает на строке после отпускания позднего
  ответа, а не раньше, то есть тест ловит саму ошибку, а не сбой окружения.
- После исправлений сам прогнал `npx playwright test` с `DEMO_LATENCY=1` и
  с `DEMO_LATENCY=0` (38 passed), `tools/smoke.py` и сборку фронтенда.
- В браузере обеими ролями проверил быстрые переключения, сохранение с
  переходом на другую заявку, карточку 103 и архивную 104.
- Прочитал diff каждого коммита: в бэкенде используется только
  `pg_query_params`, нет синтаксиса новее PHP 7.4 (`php -l` в контейнере
  7.4.33), задержки API не тронуты.

Что исправили или отклонили, если такое было?

- В плане модель предлагала API-тесты на Python и Vitest для фронтенда. Я
  заменил их одним инструментом — Playwright: он проверяет связку UI с
  настоящим API, и одна команда запускает все проверки.
- Модель хотела через `git commit --amend` убрать из первого коммита
  файлы IDE (`backend/.idea/`) и lock-файл LibreOffice. Правила агента
  заблокировали переписывание истории, и первый коммит остался как есть.
- Черновик SOLUTION.md я сократил по стилю и вписал реальное время работы.

История всех чатов и искусственно придуманные ошибки модели не требуются.
